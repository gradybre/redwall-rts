# UI-C3-R01 — Readable counters, reachable alerts and distinct workspace geometry

2026-09-14 · Adopted design correction to UI-SET-001–012/051/069, UI §1.2–1.3/§3, ALERT-R02, SET-UX-VIS-002 §4.2 and UXV-005/016/018/032. This is a layout contract, not runtime or ART-UI-12 acceptance. Source baseline `2021444c520a8bf2f0c3aecd84a034149a1fb414` (PR118); retained imagery and harnesses under `docs/validation/evidence/ui-refinement/cycle-01/` and `docs/validation/harnesses/artui12/`.

## 1. Correct the premise first

The old centered 960×720 rectangle is not the current ordinary-workspace contract. [SET-UX-VIS-002 §4.2](../ui_visual_refinement_amendment.md#42-workspaces-and-modals) already prescribes a 640-wide nonmodal workspace above the command strip, with a separate compact roster and true modal variant. The reviewed `ui_shell.gd` still places `ID_WORKSPACE` at `_geometry.modal`. This is an unimplemented amendment, not solely a missing z-order ruling. PR118 correctly proves occlusion, but its explanation based only on base UI §1.2 is incomplete. Apply the current amendment, with the top-band refinement below. Do not raise the entire HUD above every dialog.

A second visible mismatch: the NARROW capture shows Food and Fuel. Its specified second persistent counter is Population. Select IDs 002 and 006 explicitly; never take the first two entries of the six-counter array.

## 2. Resource cards: two text lines with measured space

All units below are logical pixels. Keep FOREST resource/time chrome and JOURNAL resident/community pages; the synthetic concept's paper resource tray does not override that mapping. Use the painted resource identities from ART-LOCK-001. Do not buy or regenerate assets for this correction.

Replace the 36-high resource cells with 56-high readout buttons in a 128-high resource frame. Retain frame widths: Standard **360**, Wide **480**, Narrow **176**. Resource origin stays (16,16). Standard/Wide retain three columns and two rows: local y=8,64; horizontal gap=8; width=min(144,(R−32)/3); local x=8+column×(width+8). Narrow retains Food then Population as two 104×56 cells at (8,8)/(8,64), with a 32×44 Expand button at (136,42). No resource strip is added across the world.

Within a cell reserve 4px on each edge. Put a **16px optical resource icon and 4px gap beside the caption in the first line**; the number owns the full second line. Value width is cell_width−8: Standard **101⅓**, Wide **136**, Narrow **96**. Caption uses 14px regular Sans, measured20px line box; numeric line uses18px Semibold, measured26px line box, with no extra interline gap. Combined46px plus8px padding fits56. Center the icon in the caption line. This explicit optical-size exception replaces the old24px inline resource icon; it does not shrink typography. Measure caption+icon as well as the value. Outer frames must reserve these rectangles; ornament cannot consume their text gutters. Resource readouts use one explicit focus-geometry exception: a2px ring inset1px inside the cell, contained entirely in the reserved4px padding. Keep the surface's focus color and a distinct selected cue. The external offset2 ring is not used on these touching resource rows; all other controls retain their existing ring contract. Test focus on both adjacent rows: no clipped ring and no ring painted across the neighboring caption.

Captions: Ready food / Fuel / Wood / Stone / Residents / Beds; NARROW uses Food / Residents with full Ready food meaning retained in accessibility and disclosure. No potential-food value uses this cell. HUD primary values: ready-food days with exactly two decimals and ` days`; heating-fuel days when defined; exact available wood/stone quantities with ` U`; living population as `N / 256`; assigned/legal usable bed capacity as `N / C` when its owning service supplies both. Full ledger/accessibility descriptions retain all registry fields (nutrition, reservations, idle, warm/free beds and demand context). No bed capacity is inferred from population. Secondary fields are disclosed in the ledger, not squeezed into the primary value.

**Explicit overflow exception to UXV-016:** measure the complete primary value before painting. If it cannot fit unchanged at 18px, retain the caption and replace the numeric line with **See ledger** at the normal 16px body size. Activation opens the exact, wrapped/scrollable resource record; keyboard focus announces the full accessible value and unit without automatic navigation. Keep the ledger action operable for overflow and unavailable states so the disclosure is real. This is a named disclosure state, not a shortened number, infinity, ellipsis or a falsely smaller stock. Never abbreviate to K/M, silently crop, shrink numeric text, or hide a low-food warning. Announce value changes without moving focus. Unknown data reads **Unavailable** at 16px with the actual reason, never zero or an unlabeled dash. Numeric zero stays a real number. Fuel no-demand remains distinct from unavailable; if its exact phrase does not fit, disclose it through the same ledger state.

This resolves the impossible demand to display every possible int64-sized quantity in a fixed ~100px cell. The complete exact value remains one activation away by pointer and keyboard. The primary caption always identifies the resource. Critical notices and transaction costs retain their full wrap/scroll rules; this exception applies only to compact HUD resource values.

## 3. Alerts: two genuinely reachable full cards

STANDARD/WIDE outer alert height becomes **104**; width/x/y unchanged. Keep 2px outer inset, 4px inter-card gap and the existing 36px history rail. Content height is 100. Full cards retain 12px vertical/horizontal padding and a 24px severity icon. Minimum full or summary card height is **48** in these profiles. A one-line 16px notice measures 23px; max(text23,icon24)+24=48. Two such full cards plus gap consume exactly 100. This replaces ALERT-R02's unreachable two-44px-full-card example.

Preserve ALERT-R02 priority and full-message preference: measure first full card including real adornments; use it if ≤100, otherwise its authored 48px summary. Measure the second against remaining height after gap; full if it fits, then 48px summary if that fits, otherwise history count only. No third card, independent overlapping growth, or truncated recovery text. Examples: 48+4+48 fits; 70+4+48 does not; a first full card of 101 becomes summary48 and can admit a second48. An authored summary must itself fit measured width; enforce this for every active producer/profile during content validation. It is not an automatic substring. If an unexpected runtime notice lacks a fitting summary, refuse card painting for that notice, retain its full accessible/history content and include it in the undisplayed count; other valid cards retain priority order. History must remain operable. Record an explicit authoring/fit diagnostic and fail UI qualification, rather than clipping or inventing a shortened cause. Critical integrity notices still use their required modal path.

NARROW retains outer48/card44, width≤360, y76 and one summary. Its summary-only **vertical padding is 8**, horizontal12 remains; max(icon24,text23)+16=40≤44. Vertically center the content in44. This is an explicit NOTICE summary exception to generic panel padding, not a change to full-message padding. History details retain readable wrapped full text, recovery, stable notice identity and focus return. Empty state shows only History. Critical integrity modal behavior stays unchanged.

## 4. Reserve the top band; preserve real modality

At all profiles the resource frame now ends at y144. Alerts end at120 (Standard/Wide) or124 (Narrow); time keeps its existing geometry. Define `management_top = max(128, bottom(resources), bottom(alerts), bottom(time)) + 8`, giving **152** at the supported profiles. No management body or title overlaps that band.

Ordinary WORKSPACE keeps SET-UX-VIS-002 §4.2's width≤640, command-strip-centered/clamped placement, detail avoidance, bottom=command_strip.top−8, no scrim and no full-screen input block. Its top is at least management_top. Use measured content height bounded by560 and available height. If less than248px remains, use the compact management variant.

**Compact management variant:** retain JOURNAL, z80, focus trap and SCRIM, but place its body below management_top: width=min(640,Lw−32), horizontally centered; available=Lh−16−management_top; height=min(560,available); center vertically within that available interval. Header64 and footer60 remain fixed, content scrolls. At 1280×720/150% (logical853⅓×480), body is **(106⅔,152,640,312)** with 188px between header/footer. This is intentional reflow, not a clipped 560px dialog. The scrim may dim the reserved HUD, but no opaque management content covers it. Background HUD controls are excluded from input/focus while this compact modal owns input; users close it to act on routine notices. Critical interrupt behavior retains the existing higher-priority modal/pause path. Do not let a click through a dimmed alert issue a world command.

True New Settlement, confirmation, error and other MODAL variants retain their owning centered geometry/scrim/focus contracts; do not apply the management band to every modal or invent a new pause reason. The existing pause-on-management preference applies to both management variants. No simulated-time pause is added just to solve layout. Closing removes only its own surface and returns focus; selection never opens a workspace automatically.
