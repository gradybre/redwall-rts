# 1078 — Actual paid spoil operations share the worker and receipt owners

2026-10-03. Implementation increment of 1065 and 1073. Actual terrain contacts,
village hauling, joint memory admission and composed persistence remain open.

`SpoilWork` is the concrete SPOIL_TIP purpose owner for the shared
`ModularProjects` router. It composes the actual Tips ledger, Construction,
Inventory, Reservations, Items, Jobs, Work, Gear and the single Sites Funding
arena. There is no synthetic payment publisher, second Inventory or duplicate
receipt arena. The terrain/contact provider is typed separately and fails closed
until the actual world binds it.

The owner reads immutable operation and quantity facts from the actual live
Tip/project relationship. The adopted preparation, compaction, reclamation and
empty-closure prices remain those in 1065. It resolves excavated earth through
the actual catalog. Only reclamation emits a normalized PLAIN/SPOIL_RECLAIM
earth lot; compaction cancellation returns the original metadata through
Funding's existing receipt/refund rules.

One pending admission holds a candidate tip, tile, operation and quantity.
Before Construction allocates a project, the owner rechecks source capacity,
retained work and contact qualification. The shared router allocates the actual
purpose-qualified project, then its synchronous ADMIT window permits the Tips
ledger and staged physical contact to publish. A direct ledger or owner call,
stale generation, foreign composition or expired contact provider grants no
permission.

Actual Work is the sole source of productive progress, XP and tool wear.
START validates contacts before Funding consumes delivered inputs; PRODUCTIVE
stages physical proof before Work changes state. The new router's exact Job
abort bracket discards that candidate if a later Work check refuses or accepts
zero work. COMMIT stages source and output geometry before the real Inventory
transaction. Reclamation releases source only after output commits. A blocked
completion retains both source and finite reserved output for retry without
extra labor, XP, input or durability. CANCEL releases claims only after the
actual refund settles, retaining exact-quantity earned work for a fully paid
resumption.

Publication uses captured tip/tile/project/operation identities. This matters
for CLOSE: the actual ledger retires the tip before its physical footprint is
released. A post-retirement lookup cannot be used to reconstruct those facts.
All fallible physical preparation precedes payment/source mutation, and the
provider's corresponding publication must be synchronous and non-failing.

`Tips.publisher_binding_refusal` exposes the existing binding checks without
publishing a weak reference. The owner preflights both Tips and Router before
binding either. The retained bindings identify actual objects and the real
generational World, not coincident numeric handles from another simulation.

The adapter adds no packed persistent columns or per-tip/project object. Its
one nested Publisher holds weak owner/router back-references, actual shared
owner references, one reusable integer result and pending-admission controls.
The adapter also retains one exact prepared-transition identity. These are
component wiring and synchronous scratch. They must be clear at save/load
boundaries, and their numeric/native allocation lifetimes are charged to the
joint 1072 composition before activation. Tips owns physical stock/work,
Construction owns project accounting, Router owns accepted Jobs and Funding
owns consumed receipts.

The composed tests use actual economic and worker stores with explicitly
synthetic terrain, route and contact permission. They cover actual paid
preparation and worker reuse, compaction/reclamation conservation, blocked
productive and completion retries, started cancellation loss and full
repayment, and empty closure with generational reuse. They do not qualify
actual terrain siting, underground hauling, body clearance, village activation,
runtime memory/performance or save/load. The isolated ledger tests remain
separate evidence; their synthetic publisher is never used by this adapter.
