# 0069 — UI quality requires an art pass, not just a functional theme
Date: 2026-09-11 · Status: Accepted direction; generated art candidate awaiting visual review

## Decision

SET-UX-VIS-002 revision2 incorporates [ART-UI-01–12](../design/ui_refinement/visual_art_direction.md).
The original four flat images remain structural references. A separately preserved
generated concept demonstrates the intended material/illustration quality, with
explicit deviations rather than an implicit geometry or data override.

## Why

Brendan clarified that the RTS comparison must address visual appeal. Both the
first UI and its cleaner flat target fall short in illustration, material craft,
component silhouette and setting identity. Correctness and art require distinct
review evidence; a more attractive world background cannot substitute for UI art.

## Consequences

Add painted object icons, illustrated generic species, crafted edges and distinct
container silhouettes. Wide toolbar art grows18→24px inside its unchanged52px
button; narrow remains16px. Preserve exact functional tokens, fonts, solid text
backgrounds, component bounds, runtime bindings, pause and input contracts.
Generated lettering/map/portraits never become production state or asset proof.
Native art review and Brendan's aesthetic verdict remain pending. No Meshy or
external paid asset credits are authorized for the executor.

## Source

Brendan's visual-appeal clarification, inspected first-shell capture, prior
structural image, public RTS image research and IMG-04 material reference.
The concept prompt, original bytes and provenance are retained in the repository.
