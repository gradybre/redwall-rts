# INV-GOODS-R01 — Container enumeration and stored-goods demolition gate

**Status:** adopted planning contract, 2026-09-14; implementation acceptance pending. Source links below are relative to that directory. Audited against merged `origin/master` `127c8e4` (PR 116); the supplied master copies of `inventory.gd` and `construction.gd` are byte-identical to the local copies, as are the two test files against `origin/master`.

## Ruling

**Publish container enumeration from Inventory.** `inventory.gd` shall expose a read-only, deterministic `containers_by_owner_into(owner_ref, caller_owned_refs)` query. It scans the existing finite container rows, selects only live rows whose complete stored owner `(slot,generation)` equals the requested **directory** owner ref, and writes complete **inventory-container** refs `(slot,generation)` in ascending container-slot order. The caller supplies and reuses a bounded flat pair buffer (or an equivalent caller-owned typed array); the API returns an explicit success/count and clears the visible count on refusal. It never returns internal packed columns or a mutable live view, allocates no per-container objects or saved reverse index, and does not treat a missing owner or stale output as proof of emptiness. Its maximum output is `2 * CONTAINER_CAPACITY` int32 cells; the implementation must account for the caller's scratch memory and refuse undersized buffers without truncation. A bounded scan is sufficient for this cold destructive path. Do not add a permanent owner index without a separately budgeted, synchronously maintained need. [GDD §4.2](../game_gdd.md), [ARCH-MEM-001/002/005](../systems_architecture.md), [inventory rows and queries](../../godot/scripts/core/inventory.gd), [open request](requests/OPEN.md#inventory-container-enumeration-by-owner).

**Use the query as evidence, not as permission.** `CONSTRUCTION-GOODS` owns the composition boundary between `buildings.gd`, `construction.gd`, Inventory, and the actual hauling/placement owner. `open_demolition()` is a gate: while any affected live lot, unresolved capacity claim, or occupant remains, it refuses **before** publishing a project or changing BuildingState, with the exact stranded lot refs and quantities available to notice/UI. It does not teleport goods to another container. Real jobs haul and commit each transfer first; a later demolition request re-reads the authoritative stores and may proceed only when they are clear. A live lot is counted once even when `reserved_milli > 0`; reservations are claims on that lot, not extra goods. The zero-goods case is a successful complete scan at the final gate, never a caller-supplied `goods_clear`/`can_evict` boolean. Preserve the existing occupant and furniture-user refusals. [REQ-SET-127/128](../game_gdd.md), [existing resident gate](../../godot/scripts/core/construction.gd), [inventory query and transactions](../../godot/scripts/core/inventory.gd), [MOVE-DEP-R05](2026-09-12_movement_dependency_rulings.md).

**Containment must be proved by the owner of each affected endpoint.** A building's main store is keyed by its Building directory ref. A resident satchel is keyed by the resident, a construction material container may be keyed by a Project, and a ground pile has its own endpoint; owner equality with the Building is therefore insufficient to infer physical containment. The integration owner must enumerate the affected endpoint set from the real building/room/furniture/project/footprint bindings, validate each ref and its ownership/placement, and query Inventory for each distinct affected owner. It must say which containers survive the edit and which are removed or become unreachable. A container merely near the building is not automatically building-owned; a physically affected container owned by another entity cannot be silently omitted. If an endpoint binding needed to prove coverage is absent, refuse as **missing containment contract**, distinct from a proved empty set or from a transport/capacity refusal. This is the remaining integration dependency after the Inventory query lands; it is not solved by a new read-model flag. [GDD §4.2, §5.9](../game_gdd.md), [ARCH-MEM-002/ARCH-STATE-004](../systems_architecture.md), [Construction's current uncoupled container ref](../../godot/scripts/core/construction.gd), [task 06.2](../tasks/06_buildings_rooms_logistics.md).

**The gate revalidates current state.** Existing Inventory queries carry no state revision, and container/lot refs can retire and reuse slots. A query result is only a momentary candidate list. Every demolition attempt re-enumerates and validates the building, affected endpoint bindings, container/lot generations, current lot quantities and reservations, outstanding reserved mass, and occupants immediately before its state change, without a yield or intervening Inventory/Building mutation. Multi-tick hauling uses real Inventory transfers; an earlier preview never authorizes publication. If a later optimization uses a revision token, the mutable producer owns and advances it on every relevant committed change and invalidates it across clear/load; a caller-assigned positive number is not evidence. Movement's `destination_revision` remains a distinct contact-validity contract and advances on demolition/access edits affecting admission. [ARCH-SCOPE-002](../systems_architecture.md), [MOVE-DEP-R05](2026-09-12_movement_dependency_rulings.md), [MOVE-REQ-006/019](../movement_direction_amendment.md), [Inventory generation and transaction rules](../../godot/scripts/core/inventory.gd).

**Reservations, carried goods, and equipped goods keep their existing identity.** A reserved lot remains in its container and is stranded until a valid whole-lot move carries its claim or the claim owner explicitly releases/redirects it; a partial transfer may move only unreserved quantity. Container `reserved_mass_g` is undelivered headroom, not a live lot: report it separately as an outstanding capacity claim and resolve it through its owner before removing the container; do not invent a lot to satisfy the notice count. Goods in a resident satchel remain resident-owned and travel with that resident; while the resident is still inside, the occupant gate remains authoritative. Equipped gear has a null Inventory container **only** under the gear authority and is outside container mass; it is not a hidden building lot or a second copy of carried goods. Evacuation may not silently unequip, consume, discard, release someone else's reservation, or mint a ground pile. A ground pile is an allowed destination only through its authored placement/capacity/access contract, including the inability to publish it on a destroyed or inaccessible footprint. [GDD §4.2, §5.7, REQ-SET-110/127/128](../game_gdd.md), [Inventory invariant 4, move/reserve/attach paths](../../godot/scripts/core/inventory.gd), [inventory reservation/equipment tests](../../godot/test/test_inventory.gd).

Canonical copying, retained dead-row reservation residue and §7 versioning follow [INV-CANON-R01](2026-09-14_cycle02_inventory_canonicalization.md). Dead-row residue is not a stranded live lot. This goods query does not normalize or mutate Inventory state.

## Query-ready scope and remaining engineering gaps

* **Ready as an isolated Inventory change:** `inventory.gd` stores `_c_owner_slot/_c_owner_generation` and already exposes `container_owner(ref)` and per-container lot iteration, but no enumeration entry point or owner index. Add the bounded query and test exact owner generations, deterministic ordering, stale container reuse, output capacity/refusal, and empty results. It can land without claiming the demolition gate is complete. `create_container()` accepts an owner pair without checking directory liveness; the composing owner must validate that binding and reject orphan/stale ownership. [inventory container creation and queries](../../godot/scripts/core/inventory.gd).
* **Full gate still needs composition:** `construction.gd::open_demolition()` checks occupants and furniture users and publishes the demolition project, but has no Inventory reference, no goods scan, and no hauling/evacuation coordinator. Until that composed gate exists, a pending-goods demolition must refuse before the state change. `set_material_container()` only range-checks an Inventory-container pair; it does not prove the container exists or is bound to that project. [construction implementation](../../godot/scripts/core/construction.gd), [construction tests](../../godot/test/test_construction.gd).
* Inventory transactions preserve lot conservation and refuse destroying a nonempty or mass-reserved container, but they do **not** make a cross-store Building/Construction/Inventory edit atomic. Their existing behavior is a building block for, not proof of, the composed demolition gate. [inventory transactions/destruction](../../godot/scripts/core/inventory.gd), [inventory tests](../../godot/test/test_inventory.gd).
* The current tests prove occupied-room/furniture refusals, reservation-preserving whole-lot moves, equipment partitioning, and Inventory rollback. They do not cover building-owned container enumeration, goods evacuation, exact stranded-lot reporting, changed inventory between preview and commit, or cross-store refusal immutability. [construction tests](../../godot/test/test_construction.gd), [inventory tests](../../godot/test/test_inventory.gd).

## Owning work and acceptance

`CONSTRUCTION-GOODS` (task 06.2; currently owns `inventory.gd`, `construction.gd`, and their tests in [work queue](../planning/work_queue.json)) may first land the bounded query and its Inventory tests as **query-ready**. It remains open until a separately integrated demolition gate proves containment and refusal. The work queue must assign the actual coordinator and its integration tests to this ID or an explicit dependent ID; its current four-file ownership cannot by itself express the cross-store commit. Building/room/furniture and hauling endpoint owners supply the real affected-container bindings and actual relocation; Movement supplies route/contact invalidation where access changes. The query result remains finite, caller-owned, generation-safe, deterministic and refusal-carrying. A malformed/null owner ref is refused by the query; live directory ownership is validated by the coordinator, since Inventory does not own the directory.

For the **full gate**, test empty, nonempty and reserved-mass-only stores; two lots with one reserved; resident satchel and equipped tool alongside building stock without double counting; project/ground-pile endpoints physically affected but owned elsewhere; destination capacity/access failure; mutation after preview; aborted transfer; and refusal leaving Building, Construction, Inventory and directory bytes unchanged. A successful scenario uses real haul transfers, then retries demolition: every affected lot is in a valid surviving container, quantities and claims are conserved, and no stranded lot/claim or occupant remains before BuildingState changes. Report exact distinct stranded lot refs/counts and quantities; `OpResult.value` alone cannot describe a multi-lot notice. Retest contact invalidation in the movement owner's suite. For **Section 7 schema 3**, test a full-lot transfer that allocates a new destination from the just-retired source slot, the reserved-merge residue probe, quiescent capture without hot-state mutation, strict v3 readback and explicit v2 rejection/migration behavior. [REQ-SET-128](../game_gdd.md), [MOVE-TEST-05/10](../movement_direction_amendment.md), [MOVE-DEP-R05](2026-09-12_movement_dependency_rulings.md), [Section 7 codec](../../godot/scripts/core/save_section_inventories.gd).

**Exclusions:** This ruling does not choose tier-2 demolition economics (the separate [open item](requests/OPEN.md#tier-two-demolition-basis)); does not author underground evacuation/hazard outcomes, ground-pile creation rules, a new generic reservation model, or a storage policy for furniture/rooms; and does not claim that owner enumeration alone closes all of task 06.2. Keep `REQ-SET-128` in full until the composed acceptance above passes.
