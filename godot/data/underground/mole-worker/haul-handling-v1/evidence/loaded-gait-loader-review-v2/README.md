# Loaded gait loader correction

The independent loaded-gait review found that the old on-disk NPZ size limit did not bound decompressed arrays. A real 5,259-byte compressed image materialized 4,931,584 array bytes for 4,096 keys before the 256-key refusal. `allocation-and-payload-check.json` repeats that exact allocation witness against the retained old source and records zero NumPy array materializations before the corrected refusal.

The correction reads at most 312,321 bytes into an immutable snapshot and admits at most 312,320. Before ZIP member objects, it admits only a bounded two-entry directory (at most 512 bytes, no archive comment or ZIP64 directory). Local ZIP64 headers produced by normal NumPy saves remain supported. It requires exactly `matrices.npy` and `grounding.npy`, without duplicates. Only stored or deflated unencrypted members are admitted. Every decompression read has an explicit positive limit; an understated central-directory length cannot cause an unbounded convenience read.

Both NPY headers are bounded to 512 bytes and completely checked before either array view is created: version 1 or 2, ASCII metadata, little-endian float32, C order, exact matrix shape `(n,25,12)` and grounding shape `(n,)`, integer 2 <= n <= 256, equal key counts and exact declared payload lengths. No pickle/object dtype or shape-driven NumPy decoder is called. The complete matrix and grounding payload is at most 308,224 bytes; this is an offline format limit, not a runtime/native memory admission. Finite-value checks follow the bounded reads.

The rejected directory retains the original prover, the seven new regression methods used against it, exact pins and the full 12-failure subtest log. The final source adds eight loader methods, including both-header-before-first-array proof, duplicate/missing members, compressed expansion, huge declared shape with a short payload, wrong dtype/order/shape/header/payload, directory allocation order, positive maximum-capacity stored/deflated/version-2 images and explicitly bounded decompression reads. The complete 23-case suite is run against the unchanged reviewed candidate; see `final/invocation.json` and `final/tests.log`.

All four authored geometry images and the author, rational grip prover and reproduction runner remain unchanged. The original source-only scope and open native-error, finite World support/root progression, loaded turn, BUILD set-down, runtime contact/quantity and joint allocation gates remain as recorded in `../loaded-gait-review-v1/README.md`. No source rate grants gameplay speed or work, and no Godot/shared owner source is changed here.
