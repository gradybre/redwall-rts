# Injury owner 6 — preliminary source audit

2026-09-20. Read-only discovery while ResourceNodes implementation runs. No accepted Injury contract, author dispatch or production change.

The compiled section 4 layout has owner 6 `injury`, version 1, 512 primary rows, zero child extents, 11 fields. Canonical order is five u8 columns (present, kind, airless_episode, exhaustion_latch, care_context_blocked), three i32 columns (severity, rescuer_slot, rescuer_generation), and three i64 columns (untreated_ticks, care_progress_mwu, last_incident_ordinal). Values 20992 bytes; payload 21084; block 21114; offset 8539433, followed by Jobs at 8560547. Verify field-begin and all numeric claims against the actual schema before freezing.

clear/spawn/despawn reset every row field, with rescuer null (-1,0). Presence is per resident physical row; no local 256 cap. Kind 0..5 derives from Catalog.INJURY_KIND. Severity 0..2 and kind NONE iff severity NONE. The three flags besides present are boolean; kind is not a flag. Present no-injury rows can retain incident ordinal and airless/exhaustion latch state after successful treatment. Treatment clears kind/severity, untreated ticks, care progress and rescuer, but does not clear incident ordinal or those latch/input bytes. Avoid inventing an all-zero no-injury rule.

A public set_rescuer checks patient alive, target resident Directory identity, not self, and one patient per exact rescuer pair. It does NOT require active injury, so a healthy present row with a bound rescuer is reachable. Liveness of retained rescuer refs can become stale later; saved identity policy needs explicit same-file treatment. Global Directory capacity is 352418, not resident512. Duplicate exact nonnull pairs across present rows are locally identifiable and current setter forbids them, but scope/algorithm/budget are not settled yet.

Care work accepts any positive int64 increment through checked_add and has no cap at 60000/120000; treatment consumes all accumulated progress by clearing it. Incident ordinals accept any positive signed int64, strictly increasing. Active injury therefore implies positive ordinal. Ordinal can remain positive after treatment. Untreated ticks advance while present, injured and alive. tick_all currently performs unchecked `_untreated_ticks[slot] += 1`; the boundary behavior and saved-domain policy need investigation before accepting a contract. Do not silently impose a new arbitrary saved maximum or claim a tested overflow fix.

state_bytes is a public diagnostic encoded with var_to_bytes(PackedInt64Array), not raw column concatenation. It emits only present rows: count followed by eleven values per row (row, kind, severity, untreated ticks, care, ordinal, rescuer slot/gen, airless, exhaustion, context). Tests must decode/remap explicitly or use public readers; absent rows need source-owned expected defaults, not invented private capture.

Cross-owner obligations include saved Needs presence/injury-state/health, resident Directory identity, rescuer ownership and movement care context; no live lookup may stand in for a saved-file comparison. Constructor allocates only Injury columns/math but validator must not construct it. Final authority excerpts, feasibility review, actual public history and boundary probe, contract and metadata plan remain to do.
