## 4. CONDITIONS — SMALLEST EXACT CORRECTIONS

C1. Add the three retained-history refusal witnesses above (plus the one FREE case), so the retained half has negative as well as positive evidence.

C2. Pin the authored bill key's exact Variant type. This is a reachable authoring counterexample, not a style point: `BUILD_MATERIALS`/`UPGRADE_MATERIALS`/`FURNITURE_MATERIALS` hold bare literals such as `"wood"`, which are TYPE_STRING, while `MATERIAL_KEYS` is `Array[StringName]` of `&"wood"`. `_write_bill` reconciles them with an explicit `StringName(...)` conversion. An author who writes the preflight as `typeof(key) == TYPE_STRING_NAME` would refuse every legitimate source and the validator would fail closed on a correct repository. The contract's "each key's actual string type/known membership" must say TYPE_STRING explicitly and require the same explicit conversion for membership. The same note applies to the catalog and fact dictionary keys, which are Strings, and matches the contract's already-correct choice of `Array[String]` for COLUMN_BUILDING_KEYS / COLUMN_FURNITURE_KEYS.

C3. Remove the gate-6 ambiguity. "max_workers equals the source fact for building purpose, or MAX_BUILDERS 4 for furniture" does not say where DEMOLISH and UPGRADE fall. In source, `_max_workers_for` routes FURNITURE to MAX_BUILDERS and *all three* of BUILD, UPGRADE and DEMOLISH to `max_builders_of(type_id)`. Restate as: BUILD/UPGRADE/DEMOLISH use COLUMN_BUILDING_MAX_WORKERS[type_id]; FURNITURE uses 4. Today every building entry is 4 so no behaviour differs, which is exactly why an ambiguous sentence would survive testing and then mislead later.

C4. Two source-preflight additions, both cheap and both a direct consequence of D3 (release-stripped asserts). First, require every COLUMN_BUILDING_WORK_MWU entry to be positive and exactly divisible by 4 — gate 8's demolition W depends on it, construction.gd only guarantees it via a stripped `assert`, and frozen-source-facts.json confirms it holds for all 30 rows today. Do not extend this to furniture work: no furniture demolition path exists (`open_demolition` accepts a building reference only), so its divisibility is irrelevant to every gate. Second, record "DEMOLISH has no delivery bill" as a *structural* source assumption that no data comparison covers — `_bill_count_of` is an instance method and therefore unreachable from the pure preflight — and note its failure direction is fail-closed (a future demolition bill would cause AWAITING demolition rows to be refused, never wrongly accepted).

C5. Fix where the nonmutation mutant is exercised. `entry_hygiene`'s "input before/after byte-equivalence at every refusal/success" is a real assertion but, on the *bridge* path, it cannot kill a mutating implementation: `_project_columns` assigns the record's columns into the borrowed view without duplication, so a write through the view triggers Godot's copy-on-write and the record is protected by the engine rather than by the code under test. On the *direct* path, where the caller owns the Columns instance and the array is the object's own property, an in-place write is observable. Require the mutation mutant on the direct path and say so. Note also that the allocation discriminator does not subsume it: a CoW copy of even the widest column is 663552 bytes, below the 1048576 incremental bound, so the two mutants are independent and neither implies the other.

## 5. PROBE ASSESSMENT — NO EXECUTION CLAIMED

I make no claim that the probe ran. retired-probe-a2.json records exit_code 0, 2.284 s, counts [4, 100, 0], script_or_engine_error false, with raw_log retired-probe-a2.log at sha256 f83376d2…; the log itself is not in this packet, so the counts are recorded evidence I have read but not verified. The focus runner is a minimal `_discover_suites()` override returning one path, inheriting the base runner's worker/supervisor and abort detection — an appropriate way to avoid inherited suites.

On design, four observations the contract should absorb, none blocking:

(a) The length-measurement technique is valid *because* all 18 segments are fixed-width packed types (PackedByteArray / PackedInt32Array / PackedInt64Array), whose `var_to_bytes()` length depends only on type and extent, never on content. Record that restriction so the technique is not later reused on a String, Array or Dictionary segment, where a zeroed prototype would not predict the real length.

(b) The probe is not a fault oracle. Its guards catch total-length drift (witnessed by the ±1 byte cases and the named TOTAL_LENGTH_MISMATCH) and wrong decoded type or count, but a hypothetical same-length, same-type segment transposition would decode silently. That is harmless for its actual use — it reads unforged `state_bytes()` output — provided the contract says the decoder may only be pointed at genuine store output and never at a forged image used as a negative witness.

(c) Its memory cost is test-only and must be excluded from the validator envelope in writing: it materialises the whole `state_bytes()` image, one sliced segment and one decoded segment concurrently, and re-measures all 18 prototypes on each `_decode_row` call. None of that touches the 6417408 allowance, which covers the validator and bridge only.

(d) Coverage limit, already conceded in r02 and worth keeping in the contract: the three histories are all BUILD-purpose, so UPGRADE, FURNITURE and DEMOLISH retention remains synthetic-only until the final matrix adds them.
