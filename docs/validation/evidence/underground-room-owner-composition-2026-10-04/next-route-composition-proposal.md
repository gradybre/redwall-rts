# Next route-owner composition: read-only handoff from 1163

This is an implementation proposal, not part of the frozen 1163 runtime.
Inspection uses `ebdd5daa` and unchanged current Catalog/Routes/WorldRoutes APIs.
Parent has assigned Construction the separate versioned ground-only Catalog
and actual pace artifact prerequisite. Geometry owns forthcoming shared
Profiles/Driver/Routes/WorldRoutes consumer changes; this lane must not edit them.

## Exact sequence and APIs

1. Start only from the actual mounted Session's ready, idle 1163 private tuple;
   retain it through one synchronous stopped constructor bracket. Revalidate
   current Profiles/Levels/source and original Host tuple before and after
   observations. Accept no external Owners/adoption packet.
2. Construct one actual `Movement.new(directory, null, null, transforms,
   residents)`. It is the real species/stage/revision pace owner used by Catalog.
   Its legacy navigation/pose dispatcher is not invoked. The actual underground
   Routes remains the authoritative route mover. The current host has no
   existing Movement to borrow; count the first actual instance against the
   existing Movement declaration once, never create one per actor.
3. Construct `ConnectorCatalog`, call `configure(RESERVED_BYTES)`,
   `bind_actual(profiles, levels, movement, residents, transforms,
   space.domain_copy())`, then load the accepted immutable current ground pace
   artifact with its exact digest/revision. No test builder or invented fixed
   connector may enter this path. Original version 1 requires all seven tables
   nonempty, so it cannot honestly carry ground-only content; Construction's
   reviewed format/artifact is a real prerequisite.
4. Fill one temporary `WorldRoutes.Configuration` with the original Routes,
   Owner, CoreSources, Locations, Profiles, Catalog, Levels, Movement, Residents,
   Transforms, World, Terrain and Budget. Call `WorldRoutes.configure(config)`
   before `Routes.configure`. Retain WorldRoutes in the existing
   `Owners.world_routes` slot; it strongly retains Movement and Catalog and
   weakly refers back to the original graph/space/location owners.
5. Configure the original Routes shell using actual Locations/Space/Sources/
   Buildings/Budget/WorldRoutes and the already admitted node/edge/vertex/link
   maxima. Pass the actual unchanged joint `LOCATION_AND_TOPOLOGY_BYTES`, then
   `Routes.bind_profiles(profiles, inventory, gear, carry, work, reservations,
   piles)`. A failed post-configure profile bind must preserve the exact graph
   prefix until full reset; it cannot be replaced by a second shell.
6. Call `RoomBindings.configure_room_approach(world_routes)` only after the
   real graph/profile binding is complete. The actual ordinary phase provider's
   work-face/Placement composition is separate; no contact success override.
7. Expose borrowed graph/provider getters only after final pure original tuple,
   content and reciprocal link checks. The new group creates zero endpoints,
   Rooms, edges, actor routes, Sites, WIP or paid inputs. Root's actual natural
   anchor/room UI/dispatch composition consumes these owners afterward.

## Lifecycle and ownership proposal

Own Session, Retirement, minimal SettlementSystem public mount/stop wrapper,
existing Session/Host/Retirement tests, a new stateless
`underground_route_composition.gd` (+UID), its new test (+UID), decision/evidence.
Do not edit Routes, WorldRoutes, Profiles, Driver, Catalog, Movement, UI or main.
The existing private integer state/prefix can represent the extra constructor
steps; no second owner packet or per-resident state is proposed. Before Routes
stores any new binding, unpublished candidates may drop. After graph binding,
retain every original object and use a specifically derived private prefix
retirement, preserving the normal complete guards. This needs exact code review
against the final Geometry consumers before implementation.

## Retained and constructor budget

- Catalog reserves exactly 190,448 B (paired tables plus fixed/native allowance).
- WorldRoutes reserves 163,840 B (159,744 paired certificate bytes + 4,096
  controls). Together 354,288 B use their existing 524,288 binding envelope,
  whose remaining contents are already globally assigned, not new free space.
- Routes and Locations share the existing 1,048,576 B joint envelope. Use the
  accepted maxima/source formula; no cap reduction or growth is proposed.
- The single actual Movement must be reconciled with the existing baseline
  declaration; constructing it for the first time is not a second budget.
- Configuration has thirteen borrowed references (416 B under the same
  provisional 32-byte convention) and a provisional 256-byte object header.
  Its Domain copy/decode/constructor overlap needs a new exact phase census.
  The 1163 constructor-only reuse is a candidate location for those temporaries,
  not permission to add 672 B to its prior peak without recounting parameters,
  live objects and the final loader's own decode allowance.
- Existing `Owners.world_routes` and Scope Catalog/Movement pins already have
  reference slots. No new tuple member is proposed. Native allocation and any
  new caller stack remain unqualified until the next source census/review.
