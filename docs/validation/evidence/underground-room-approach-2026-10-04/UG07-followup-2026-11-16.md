# UG07 follow-up: production room/equipment order workflow remains blocked

Date: 2026-11-16  
Branch: `codex/underground-ug07-recovery-20261116`  
Scope: UG07-owned follow-up evidence only. No integration queue, demo-entry, or root-held sublease files were changed.

## Finding

The source tree already has a synchronous, fail-closed room-layout path and an
atomic room/furniture batch path. `RoomLayout` validates all drafts together,
revalidates at commit, and submits one transaction; its current regression
suite covers refusal without partial publication and successful single-batch
submission. That core is not enough to claim the UG07 player-facing acceptance
flow.

Two authoritative inputs required to complete the production flow are absent:

1. Production furniture geometry/access profiles. Decision 1059 says
   equipment heights, install/use offsets, and occupied volumes are missing,
   and explicitly rejects inferred defaults or synthetic contact offsets
   (`docs/decisions/1059-room-purpose-catalog.md`, “Authoring items deliberately
   left as proposals”). `RoomLayout._definition_refusal` requires positive
   authored height plus non-empty install and use contact data. Inventing those
   values here would make test geometry into gameplay authority.
2. Runtime/demo planner composition. The production save-owner map states that
   production composes no `RoomLayout`, `RoomProjects`, or `SpoilTips` instance
   (`godot/scripts/core/settlement_save_owners.gd`, section 6). The demo/input
   host is held outside this follow-up's ownership. Adding a wrapper module
   without that host and without production profiles would remain unreachable
   or non-authoritative, not a player-facing workflow.

The existing fail-closed behavior must remain in place until both inputs are
authored and integrated by their owners. No coordinator shim, guessed profile,
or permissive acceptance rule was added. UG07 acceptance is therefore still
open; this note is a blocker record, not a claim that the lane is complete.
